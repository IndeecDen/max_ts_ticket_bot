# Вложения в обращениях

При первой публикации новой заявки бот ставит в очередь пересылку только первого сохранённого сообщения, если оно содержит вложения или само является пересылкой. У пересланного сообщения будет подпись с номером заявки. Отправка выполняется через MAX `link: {type: "forward", mid: "..."}`.

Используется исходный `body.mid`, а не URL файла. Бот не скачивает файлы и не переносит пользовательские клавиатуры в свои карточки. Одно исходное сообщение с несколькими вложениями пересылается одним заданием. Карточки заявки продолжают отдельно редактироваться при смене статуса.

Задание и исходный ID сохраняются в SQLite в той же транзакции, что карточки. Повтор обработки, смена статуса и перезапуск не создают повторную пересылку. Применяются общие ограничения скорости, обработка HTTP 429 и ручная сверка `uncertain`/прерванного `sending`. ID подтверждённой пересылки сохраняется для последующего обслуживания.

## Ограничения

- Последующие сообщения автора сохраняются в обращении, но не пересылаются в рабочий чат и не обновляют текст карточки. Через `/request` доступны сохранённый текст и перечень типов вложений, а не повторная отправка файлов.
- Для пересылки нужен непустой `body.mid`. При его отсутствии исходный JSON сохраняется, но задание пересылки не создаётся.
- Уже опубликованные ранее карточки не получают исторические вложения при обновлении версии.
- Удалённый исходник, ограничения пересылки или недостаточные права MAX могут привести к отказу. Автоматической замены пересылки скачиванием/повторной загрузкой пока нет. Ошибка видна в очереди доставки.
- Пересылка выполняется только в рабочий чат; в клиентский чат оригинал повторно не отправляется.

Поле `outbox.forward_mid` добавлено миграцией 14 → 15. Текущая схема релиза v1.0.5 — 19. Перед серверным обновлением используйте штатный скрипт с резервной копией.

Контракт проверен по [NewMessageBody](https://dev.max.ru/docs-api/objects/NewMessageBody) и [официальным структурам SDK MAX](https://github.com/max-messenger/max-bot-api-client-go/blob/main/schemes/schemes.go). Автономные тесты проверяют запрос API, отсутствие дублей, направление пересылки, миграцию и неопределённый результат. Живая проверка файлов, изображений, видео и аудио в MAX ещё обязательна; успешное отображение всех типов пока не подтверждено.
