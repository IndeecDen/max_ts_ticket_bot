# Подготовка релиза 1.0.1

Статус: кандидат для испытаний, не опубликованный стабильный релиз. Версия 1.0.1 запрошена для GitHub; целевой репозиторий — [IndeecDen/max_ts_ticket_bot](https://github.com/IndeecDen/max_ts_ticket_bot), предоставлена отдельная тестовая Debian 13.

## Что входит

Независимый бот MAX: приём Webhook, сохранение событий и очередь доставки, заявки и роли, меню, отчёты, расписания и объявления. Добавлены пересылка исходных сообщений с вложениями по `mid`, имена специалистов и текст обращения в рабочих списках с названием и ссылкой на исходный чат. Схема базы — 16; форматирование сохраняется в очереди доставки, существующие задания сохраняются.

Средства эксплуатации: установщик Debian 13/Ubuntu 24.04 с вводом профиля и systemd, подготовка Nginx/подписки, обновление отдельными версиями, проверенные резервные копии, ежедневный таймер и явная очистка. CI настроен, но на GitHub ещё не запускался.

## Сборка архива

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/build_release.py --version 1.0.1 --output dist/max-ts-ticket-bot-1.0.1-candidate.zip
```

Сборка не перезаписывает существующий файл. Для повторной сборки укажите другой путь. Архив включает исходники, тесты, документы, скрипты, unit, workflow и `.env.example`; произвольные файлы из рабочей папки не включаются. Ссылки в исходниках отклоняются. Это не поиск секретов внутри исходного кода: перед публикацией нужен просмотр включённых файлов.

В корне архива находится `SOURCE_MANIFEST.json` со статусом `candidate`, версией и SHA-256 каждого исходного файла. SHA-256 самого ZIP выводится сборщиком. Текст нормализован в LF; временные метки и порядок файлов фиксированы. Повторная сборка одинаковых файлов одним окружением даёт одинаковый ZIP. Контрольные суммы подтверждают целостность, но не подлинность автора.

| Проверка | Состояние |
| --- | --- |
| Тесты из архива на Windows/Python 3.12 и Debian 13/Python 3.13.5 | 214 пройдены на каждой системе |
| Bash и systemd-analyze verify на Debian 13 | Пройдены |
| Сборщик: отсутствие runtime-файлов, повторяемость, запрет перезаписи | Проверено автономными тестами |
| GitHub Actions: Ubuntu/Windows, Python 3.12/3.13 | Запускается в ветке кандидата; результат проверить в Actions |
| Чистая установка Debian 13 и Ubuntu 24.04 | Не выполнена |
| HTTPS, подписка и реальные события MAX | Не выполнена |
| Реальные пересылки файлов/фото/видео/аудио и XLSX | Не выполнена |
| Перезагрузка сервера, обновление и пробное восстановление | Не выполнена |

На отдельном сервере последовательно:

1. Распаковать кандидат, выполнить `sudo bash scripts/install.sh`, сохранить настройки через мастер и проверить службу/таймер. Команды: [установка](LINUX_INSTALL.md).
2. Подготовить HTTPS, проверить маршрут и зарегистрировать подписку. Отправить тестовое обращение в разрешённый чат; убедиться, что карточки появились, а роли ограничивают действия.
3. Проверить ожидание ответа, взятие/закрытие/отмену, статистику, Excel и исходные сообщения с разными вложениями. Проверить отказ при недоступном исходнике и отсутствие автоматических дублей после неопределённой отправки.
4. Перезапустить службу и сервер; проверить продолжение ожиданий, доставку и ежедневную копию.
5. Создать копию и восстановить её **в отдельный каталог**. Проверить базу и файлы. Не запускать восстановленную копию с production-профилем параллельно основной службе.
6. На тестовой установке выполнить обновление, проверить сохранение заявок/ролей и остановку при ошибке. См. [обновление и восстановление](BACKUP_UPDATE.md).
7. Записать ОС, Python, результат каждого сценария и обнаруженные ошибки без токенов и текстов реальных обращений.

После успешных проверок: согласовать точный состав файлов Git, запустить CI в целевом репозитории, создать тег `v1.0.1` и релиз с описанием и контрольной суммой проверенного архива. До этого кандидат не объявляется готовым стабильным релизом.

Ограничения кандидата: [README](../README.md#ограничения-и-проверка-перед-запуском), [пересылка вложений](ATTACHMENTS.md). Прямое скачивание/повторная загрузка при отказе пересылки, личные диалоги без `chat_id` и автоматическая замена удалённых карточек остаются вне текущей реализации.
